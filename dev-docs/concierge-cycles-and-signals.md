# Concierge cycles, signals and digests (#8261)

Level 8 of the Platform Concierge (PRD `platform-concierge.md`, sections 6.1, 6.3, 6.11; decisions B10, B13, B18, B22). Code: `backend/app/services/concierge/` (`fleet_seed.py`, `cycles.py`, `signals.py`, `digest.py`, `cycle_access.py`, `turns.py`), `api/v1/platform_health_cycles.py`, `services/builtin_tools/health_orchestrator.py`; migrations `c8cnc8254081` (cycle runs, schedule marks, the one-open-cycle index) and `c8cnc8254082` (signal states).

## The fleet

`fleet_seed.seed_concierge_fleet` (called by `provision_builtin_content` after the skill seed, `CONCIERGE` on, XTM One, copilot and dev modes) creates five company-managed agents keyed by slug (`concierge`, `concierge-memory-steward`, `concierge-quality-analyst`, `concierge-flow-lab`, `concierge-experimenter`), their manual-trigger assignments, a company-managed fleet led by the orchestrator, and its company-managed workspace.

The orchestrator, its fleet and its workspace go by the Concierge's name (`naming.py`): Settings > Concierge's `name`, else the platform mode's default, "Alfred" in copilot mode and "Concierge" otherwise. The seed creates them under it, and renames the rows that still carry a default name when the mode changed; saving a new name renames the rows that carry the previous one (`settings.save_concierge_settings`), so a row renamed by hand keeps its name. The personas never carry the name (invariant 16): it is what people read, served to every signed-in user by `GET /concierge/name`, and the web app renders it as text or an ICU value, never as a message id. The REST refusals of `POST /cycles` and the budget line of `GET /concierge/budget` carry it (`CycleStart.message(name)`, `budget.refusal_message`, `str.replace`, never `format`); the orchestrator's tools say "Concierge", so no administrator text reaches a model.

The agents are **not** built-in: the PRD makes them editable like any agent, and built-in agents are read-only in XTM One mode. So the seed creates each one once and afterwards only writes what nothing else may: the fleet role (`identity.set_concierge_role`), a missing fleet membership, a missing seeded skill. A personal agent holding a fleet slug is never adopted. None of them carries `agent_builder`, and every seed takes off them the groups that read as the acting user with no consent check (`fleet_seed.NON_CONSENT_TOOL_GROUPS`: `observability`, `platform_insights`); `concierge_diagnosis` is their consent-aware read. Each seeded assignment carries a finite `max_iterations` (`FLEET_MAX_ITERATIONS`, 15 for the digest).

## Cycles

Every Concierge run starts in `cycles.start_cycle`: level 1's `budget.open_cycle` (licence gate, caps) inside a savepoint, a `concierge_cycle_runs` row, then `trigger_assignment` with `trigger_context["concierge_cycle_id"]`. The run never takes the requester's identity (`triggered_by_user_id` is not passed); the requester is recorded on the cycle. Nor does it take the assignment's owner: a fleet agent's run nobody triggered has `user_id` NULL (`assignment_engine._execution_identity`), so it is a company-managed run with no user and acts as the Concierge alone: the engine never falls back to the agent's owner for it (`_acting_identity`), so its tools, quota (the platform-wide tiers), provider exclusions and variables are a run with no account's. What it delegates acts with no user either: the task row is recorded under the fleet agent's owner (`identity.concierge_delegation_owner_id`, the row needs one) and marked `concierge_alone`, its child run has no user, and the worker runs its turn with none, where the Concierge groups are wired as the engine wires them (`agent_chat._add_platform_builder_tools`). An administrator's own chat or "Run now" still acts as that administrator. Inside a Concierge run or turn no agent tool takes the admin bypass (`helpers.agent_tool_admin_bypass`), the trace tools refuse another agent's traces, and `platform_insights` refuses.

- **One open cycle per target**: a partial unique index on `concierge_cycles` (`(target_type, target_id) WHERE status = 'open' AND target_id IS NOT NULL`), declared on the model and in the migration. A second request gets the `IntegrityError` and answers `cycle_open` with the open cycle's id: the database decides, not a read-then-write. Fleet-wide cycles are not unique per specialist at the table level (level 1's budget opens several); a schedule does not fire while the cycle it started last is still open.
- **Schedules** (`run_due_schedules`) read the cron of each fleet-wide cycle from `ConciergeSettings.schedules`; `concierge_schedule_marks` keeps the last firing and its refusal, so a refused firing waits for the next occurrence and a first sighting never fires.
- **Settling** (`settle_cycles`) books on the cycle what each ended run of its tree spent (the run and every run delegated from it, by `parent_run_id`: the sum of their `llm_traces`, once per run, a run with no trace yet waited for two minutes), stops the tree's runs once a cap is reached, and closes the cycle once the whole tree ended (`completed`, `failed`, `budget_reached` when a cap was reached, `cancelled`). It closes cycles still open after 24 hours and builds every missing digest. Before it, the tick charges each Concierge evaluation that ended (`evaluations.settle_concierge_evaluations`) and settles running experiments. It runs with the flag and agentic AI off too.
- The scheduler step is `autonomous.py` 9c (`cycles.concierge_tick`), every tick.

## Signals: cadence and cost (PRD section 13)

| Signal | Cadence | Reads |
|---|---|---|
| `feedback_drop` | 15 min | Agents rated in the window (`annotations` on `(agent_id, updated_at)`, web thumbs through `message_feedback.updated_at`), then `annotations.agents_weighted_score_window` for those only: three grouped queries per window, whatever the number of agents |
| `failure_spike` | 15 min | Assignments and flows with a run settled since the last pass (bounded by the indexed `created_at`), then their last N settled runs of the last 90 days (`ROW_NUMBER() OVER (PARTITION BY ...)`) |
| `cost_drift` | 1 h | `llm_daily_stats` (`source = 'assignment'`), two windows of whole days: `total_cost / trace_count` per agent |
| `model_change` | 1 h | The agents' own model columns, the routing model and the platform default |

No signal reads the Concierge's own sandbox copies (`is_sandbox`): their runs are its experiments. No signal reads `llm_traces`, `llm_spans` or ClickHouse: every input is in PostgreSQL whatever the trace store, so a large ClickHouse deployment adds no cost here. The pass marks share `concierge_schedule_marks` (`signal:<kind>`), so the cadence holds across replicas and restarts.

Signals are **edge-triggered** (`concierge_signal_states`): a crossing starts an investigation (`fleet_assignment("investigation")`, the orchestrator) on its target; staying crossed starts nothing; clearing re-arms it. A crossing refused for a passing reason (budget, licence, AI off) is retried on the next pass; one refused because a cycle is already open there is consumed. At most 10 cycles start per signal per pass. A model change re-arms at once, and its new model is recorded only once a cycle takes it: a change refused for a passing reason, or past the 10 per pass, is seen again on the next pass. A pass whose evaluation fails is retried at its next cadence.

## Digest

`digest.build_digest` reads the rows of the cycle's window: level 5's consolidation counts, level 6's findings and experiments, level 3's proposals by the fleet's agents (filed, applied, rolled back, by verdict), level 2's dry-run writes, and the cycle's own spend. A section whose owner is not installed or fails is listed in `unavailable`, never reported as 0. `status` is `completed` only for a completed run with nothing skipped. The run's own report (`result_summary`, asked in the platform language through the trigger payload, invariant 16) is kept as `narrative` and rendered as untrusted markdown.

## Access (`cycle_access.py`)

One rule for REST, the `concierge_orchestrator` tools and the platform MCP server: a person reads the cycles and signals of targets they manage (`can_manage`; administrators everything) and may request a cycle on such a target; a target they cannot see is a 404. In a Concierge run (`identity.current_concierge()`) the tools read the supervision scope, and `request_concierge_cycle` is not offered (a cycle's run never starts another). Evidence links (`evidence_links`) are given only where the viewer may open the item. The Improvements inbox (`GET /improvements`) pages in SQL for an administrator; a non-administrator's listing (one agent or one target) is read whole, so its total and pages count only what that person may read.

## Turn scope (`turns.py`)

`agent_chat.run_agent_chat` is wrapped by `concierge_turn_scoped`: every turn acts as the principal its own agent and user make it (a user id that names no user is not "no user": that turn acts as no principal), so a specialist delegated to by the orchestrator acts with its own role, and a non-fleet agent consulted by a Concierge run acts as no principal. A sandbox turn (a copy's, or any turn inside a sandbox case) keeps the principal its runner holds.
