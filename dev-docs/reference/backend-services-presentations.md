# Services: presentations, reports, templates and Video Studio

Service map rows for presentation specs, persistence, editing, export, review comments, sharing and public links, reports, template containers and the Video Studio in `backend/app/services/`; the binding rules live in `backend/app/services/AGENTS.md`.

## Service map

| File | Purpose |

| `presentation_patch.py` | The surgical edit engine behind the `edit_presentation` built-in tool: `apply_operations()` applies an ordered list of `OPERATIONS` (slide / block / deck / text ops) to a validated deck spec and returns the patched spec plus a per-slide account, `verify_untouched()` proves every slide the operations did not name canonical-JSON-identical to the baseline (`canonical()`), `summarize_patch()` renders that account, `MAX_OPERATIONS` caps a call (a burst past it is a rewrite in disguise, refused before anything is applied), `coerce_revision()` reads the tool's `expected_revision` with the lenience of a slide number (int / integer-valued float / digit string, from 1), `LAYOUT_DECK_FIELDS` (`theme`, `aspect_ratio`, `chrome`) names the deck-level fields drawn on every slide — the only ones whose change widens the post-save layout check to the whole deck; a deck `title` or `transition` change draws nothing on a slide — `parse_slide_selection()` is the `get_presentation` `slides` selector, `describe_operations()` the schema-side contract list, `search_text()` the read-only search behind the `search_presentation_text` tool (every occurrence with its slide, block address - `locate_text_field()` - and field path; case-sensitive / whole-word options) over `iter_text_fields()`, the one walk `replace_text` also counts with, so the search covers exactly the fields a replacement would touch. Pure functions, no DB: the tool in `builtin_tools/presentation.py` owns the load (`load_writable_presentation(..., for_update=True)` — a `FOR UPDATE` row lock, so the baseline is the latest committed spec and concurrent editors serialize), the re-validation (`validate_spec`, the same guard as a fresh deck — a slide still wearing a retired v1 layout is upgraded on the way), the save and the post-save layout check narrowed to the written slides (`presentation_layout.narrow_layout_report`). Full design: `dev-docs/presentations.md` > "Surgical edits". |

FOR UPDATE` held to the caller's commit, so two first-time resolves racing on one thread stamp it once (the loser waits, reads it resolved, no-ops); a plain read never passes it; `can_manage_comment()` is the single permission gate (deck manager tiers `MANAGE_TIERS` or the author); `count_open_comments()` is the grouped SQL COUNT of open root comments that feeds `open_comment_count` on the serializers AND the tool's "Open review comments left: N" line (never recount comments in Python); `resolve_slide_anchor()` / `unknown_slide_error()` check a slide id with one wording for both surfaces, in the presentation's own nouns (`unit_noun` / `whole_noun` from `presentation_spec`); `format_comments_for_agent()` / `format_open_comments_for_agent()` render the bounded digest (`MAX_REPLIES_PER_THREAD` most recent replies per thread, `MAX_DIGEST_CHARS` overall — past them, counted rather than printed); `serialize_comment()` is the API shape; `CommentError` (message + `status_code`) is the typed refusal both surfaces relay verbatim. Full design: `dev-docs/presentations.md` > "Collaboration". |
| `share_principals.py` | The people and groups a share grant names, as an AGENT TOOL reads and writes them - the ONE reading shared by the `share_presentation` tool and the agent builder's per-user agent sharing (`update_agent users=...`, `get_agent`): `principal_entries()` reads a `users` / `groups` argument however the model spelled it (a list, a JSON list in a string, a comma / semicolon / newline separated string, `Ada <ada@x.com>`); `resolve_principals()` matches each entry to an EXISTING account (by id or email, case-insensitive) or group (by id or exact name) in one query per kind, and `ResolvedPrincipals.refusal()` refuses the whole call naming every entry that matches nothing (nobody is invited) or a deactivated account to grant; `stored_grants()` / `entity_grants()` read one kind of grant as stored (no tier = `read_only`, a non-UUID skipped like the SQL predicate skips it); `plan_grants()` turns `add` / `remove` / `replace` of one kind into the list to store and its `GrantDelta` (added / removed / retiered / unchanged / not shared); `load_principals()` names every grant of an entity (`PrincipalIndex`, "a deleted account" for one gone), one query per kind and none for an entity no grant names; `SharingChange` is the PATCH-shaped body `apply_user_share_fields` reads; `MAX_PRINCIPALS_PER_CALL` bounds a call.
