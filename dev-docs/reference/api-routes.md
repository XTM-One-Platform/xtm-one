# API routes

The root `AGENTS.md` keeps one line per entry, because every agent session loads it; this file holds the full contract. Add detail here, never to `AGENTS.md`.

## API Routes

| Prefix | Purpose |
|--------|---------|
| `/api/v1/agents` | Agent CRUD, templates |
| `/api/v1/assignments` | Assignment CRUD, trigger, execution logs, HITL respond/dismiss/followup, the open action requests on a paused run (`/runs/{id}/action-requests`), bulk operations |
| `/api/v1/knowledge-bases` | Knowledge base CRUD, document management |
| `/api/v1/integrations` | Integration CRUD, catalog, OAuth, test; an OAuth integration shared without its account (`per_user`): `DELETE /{id}/my-credential` (the caller disconnects their own), `GET /{id}/credentials` and `DELETE /{id}/credentials/{user_id}` (its managers); a person connects theirs with `GET /{id}/authorize` |
| `/api/v1/integrations/{id}/github-webhooks` | GitHub repository webhooks the platform manages for an integration: list, create, delete |
| `/api/v1/exposure` | Who can use a resource a person lends, and a preview of what a sharing change would lend or take back (`resource_exposure.py`, read-only) |
| `/api/v1/integrations/{id}/lmstudio` | LM Studio console (`api/v1/lmstudio.py`), for the integration's managers, AI on, every server call on the integration's relay route (none: 409): `overview` (route, server URL, linked provider), `models`, `models/load` and `models/unload`, `downloads` and `downloads/{job_id}` (writes for the server holder: an admin for a company-managed integration, the owner otherwise), `llm-provider` create / adopt, `llm-provider/{config_id}/models`, unlink (admin, company-managed routed integration). Server and relay failures answer 424 / 404 with `detail = {code, message}` |
| `/api/v1/integrations/{id}/openrouter` | OpenRouter console (`api/v1/openrouter.py`), for the integration's managers, AI on: `overview` (key spend, credits, linked provider), `activity`, `models?kind=chat\|embeddings`, `model-endpoints?model_id=`, `keys` CRUD (management key; writes for the account holder), `llm-provider` create / adopt, `llm-provider/{config_id}/models`, unlink (admin, company-managed integration). OpenRouter refusals answer 424 / 429 / 404 with `detail = {code, message}` |
| `/api/v1/integrations/{id}/supabase` | Supabase database access probe (`api/v1/supabase_console.py`), for the integration's managers: `POST probe` with the stored settings overridden by the body (`db_password` left out or masked = the stored one) answers the projects, login roles (platform roles left out, RLS bypass flagged) and connection hosts the access token reads, then, logged in as the role, its databases, whether it bypasses RLS, the functions it may execute and the tables it can still read directly. A part that fails is `null` with a fixed sentence in `errors`; nothing is stored |
| `/api/v1/integrations/{id}/opencrq` | OpenCRQ version card (`api/v1/opencrq.py`), for everyone who can open the integration: `GET compatibility` answers `{reported_version, manifest_source (registration \| none), manifest_state (current \| pending \| unavailable \| not_accepted_default_token \| null), fingerprint (first 12 hex characters), received_at, tool_count, hidden_tools[{name, missing_procedures}], limited_tools[{name, fields[{procedure, path, kind (unknown \| missing)}]}]}`, computed from the manifest the registration stored through `providers/opencrq/procedure_manifest.py` and `input_contract.py` like the tool build, so the card and the gate agree; `hidden_tools` and `limited_tools` only when `current`. 404 for an integration that is not OpenCRQ or not visible. Never calls OpenCRQ: an integration with no registration answers `manifest_source: "none"` |
| `/api/v1/channel-bots` | Channel bot CRUD, catalog, tools (Slack, Teams, WhatsApp, Telegram, Discord, Google Chat) |
| `/api/v1/agent-accounts` | Agent accounts: owner-only CRUD, sync, decisions, replies and activity analytics, simulator, pickers, approval queue; public `/notifications/{provider}` push endpoint (`dev-docs/reference/agent-accounts.md`) |
| `/api/hooks` | Webhook receivers (`api/v1/webhooks.py`): `/assignments/{assignment_id}` (an assignment's webhook trigger), `/integrations/{integration_id}[/assignments/{assignment_id}]` (integration events), `/providers/{provider}` (provider-level deliveries); `/{agent_id}/{path}` is the deprecated per-agent form |

Session JWT only, for every route of the router, the re-mounted handlers included (`APIRouter(dependencies=[Depends(web_chat_user)])`; `Authorization: Bearer` through `get_current_user`, so a session that ended answers `401 session_expired` and the Terms of Use gate applies; `require_chat_enabled` only on send, steer, approve, `POST /chat/sessions` and upload, so reads, a session's own `PATCH` / `DELETE`, Stop and skip-wait stay open with AI off; an open stream whose session ends closes on a `session_expired` frame); the two streams skip the admission limiter |
