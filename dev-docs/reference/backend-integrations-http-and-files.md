# Integrations: shared HTTP utilities, files and stale references

The full contract of `integrations/http.py`, of file delivery (`file_delivery.py`, live artefacts, social media) and of stale-reference reporting; the rules live in `backend/app/integrations/AGENTS.md`.

## Shared HTTP Utilities (`http.py`)

All integration providers share common HTTP error handling and token management utilities from `backend/app/integrations/http.py`:

| Export | Purpose |
|--------|---------|
| `format_http_error(resp, provider, action)` | Builds human-readable error strings from non-success HTTP responses (401, 403, 404, 422, 429, 5xx) for LLM context. Use instead of `resp.raise_for_status()` inside tool functions. |
| `required_scopes(resp)` | The scope names a 403 body says are missing (`requiredScopes`, `requiredGranularScopes`, `missingScopes`, top level, in `context` or in `errors[*].context`), the same reading `format_http_error` appends as `Required scopes: ...`. HubSpot's `_throttled` uses it to name the missing scope and the tool that needs it. |
| `format_network_error(exc, provider, action)` | Formats network exceptions (connection errors, timeouts) for LLM context. Use in `except` blocks wrapping HTTP calls. |
| `parse_compound_token(token, field_count, defaults?, greedy_last?)` | Splits `||`-delimited compound tokens (e.g. `base_url||api_key`) into typed tuples. Used by providers that store multiple credentials in a single field. Pass `greedy_last=True` when the LAST field is a user-supplied secret that may itself contain `||` (Splunk token, ServiceNow/Qualys password, Sumo Logic access key, Tenable secret key). |
| `operator_base_url(raw, strip_suffix?)` | The instance URL an operator configures for a self-hosted provider (GitLab, Mattermost): `scheme://host[:port][/path]` without a trailing slash, or `None` for anything but http(s), a URL with credentials, a query or a fragment (they would change where the token goes or what the API path means). Private hosts are accepted: a self-hosted instance often lives on the private network. `strip_suffix` reduces a pasted API root (`/api/v4`) to the instance URL. |
| `is_publish_allowed(channel_id, allowed_ids)` | Shared channel/recipient whitelist check used by all channel bot providers. |
| `safe_request(client, method, url, provider, action, *, expected_statuses?, retry_statuses?, **kwargs)` | Standardised request wrapper: formats HTTP/network errors for the LLM and retries HTTP 429 with decorrelated jitter anchored at the `Retry-After` floor. Pass `retry_statuses=TRANSIENT_RETRY_STATUSES` (502/503/504) on IDEMPOTENT calls (reads, queries) whose upstream sits behind a flaky gateway/proxy so transient blips are retried instead of surfacing as hard tool failures (Grafana does this for all reads). Never opt mutations in — a write could be applied twice when the first attempt succeeded behind a failing proxy. A write that is idempotent by nature may opt in, bounded by `max_total_seconds`: GitHub's `request_github_reviewers` retries `TRANSIENT_RETRY_STATUSES | {404}` for 15 s, since GitHub answers 404 on a pull request created a moment before and requesting a reviewer twice keeps one request. |
| `AutoRefreshClient` | httpx-like async context-manager client that auto-refreshes OAuth tokens on 401/403 and retries once. Uses shared connection pool limits (max 100 connections, 20 keepalive). Call `refresh_once()` directly when the upstream reports auth failure *inside* a 200 response instead of as a status code — OpenCTI answers an expired token with `AUTH_REQUIRED` in the GraphQL `errors` array, which the 401/403 path cannot see. The single-refresh budget is shared between both paths. Its refresh log lines name the request path only, like `safe_request`: a credential a provider takes in the query string never reaches the logs. |
| `RefreshableHeaders` / `ensure_fresh_token(headers, refresh_fn)` / `bearer_seconds_remaining(headers)` | Keep a short-lived bearer JWT valid across a long run. Platform-managed integrations (OpenAEV / OpenCTI / OpenCRQ) authenticate with a cross-platform JWT whose TTL is 10 minutes, minted ONCE at tool-build time, so an autonomous run outlives it and every later call fails. Build the provider's headers as `RefreshableHeaders(..., refresh_fn=...)` and call `ensure_fresh_token` before each request: the JWT is re-minted just BEFORE it expires (coalesced across concurrent callers, mutating the shared dict in place) rather than after the peer rejects it — the proactive complement to `AutoRefreshClient`'s reactive retry. No-op for a static API key, which has no callback and no readable expiry. |
| `RateLimiter` / `get_shared_rate_limiter(key, *, rate, capacity, max_concurrency?)` | Process-wide, per-key token-bucket rate limiter (with an optional concurrency cap). Use it to PREVENT a burst of parallel tool calls from hitting a strict per-account rate cap simultaneously (the complement to `safe_request`'s 429 retry). Key it on `app_token_cache_key(provider, token)` so every concurrent caller for the same account shares one bucket. HubSpot uses this to stay under the CRM Search API's 5 req/s account cap; `fetch_image_asset` keys one per image host. `slot(admit=...)` runs a check once the concurrency slot is held and before a token is waited for (a caller whose target started refusing it leaves at once), and the registry never evicts a limiter a caller is inside (`in_use`), which would double that key's concurrency. |
| `PLATFORM_USER_AGENT` | The one User-Agent the platform announces on its outbound requests, carrying the contact URL public hosts ask automated clients for (Wikimedia's User-Agent policy among them). Send it whenever a provider calls a public API that wants an identifying User-Agent (RSS feeds, NVD / KEV / EPSS, the free Ransomware.live tier); services send it too (`web_fetch.USER_AGENT` is its re-export). Never write the string out: `tests/test_platform_user_agent.py` fails on a copy. The headless browser keeps its own `FiligranCopilot/1.0 (Browser Tool)`. |
| `format_entity_list(items, formatter, noun=, total=, plural=)` / `plural_noun(noun)` | The header and body of a list or search answer: `Found N <nouns>:` in correct English (`entities`, `entries`, `addresses`: `plural_noun` inflects the last word; a caller whose plural is elsewhere, `group with IOCs`, passes `plural=`), and `Found 30145 entities, showing 2:` when *total* exceeds the page, so a model never reads a page as the whole result. |
| `clip_text(text, limit, read_call)` | The head of a long third-party text a LISTING shows: the text whole under *limit* (or with `limit=None`, for a single-item read), otherwise cut at a word boundary and ended with `... [truncated, N more characters: read it in full with <read_call>]`, *read_call* being the exact call that returns it whole. Never cut a text a model reads with a bare `…` or slice. Used by the Teams message listings and the OpenCTI entity / relationship / container listings. |
| `oauth_token_grants.get_grant_token(config)` | OAuth2 access token for a `TokenGrantConfig` — client credentials (`TokenGrantConfig.client_credentials`) or the password grant (`TokenGrantConfig.password_grant`, `username:password` plus an optional client): cached per configuration until shortly before expiry, concurrent callers coalesced onto one request, `force_refresh=True` after a 401. `post_with_client_auth()` is the client-authenticated POST on its own (Basic, one fallback to body credentials; a public client sends its id). Token URL behind the destination guard, connection pinned, client certificate presented. |
| `oauth_device.start_device_authorization` / `poll_device_authorization` | OAuth2 device authorization (RFC 8628): asks for a user code, keeps the device code in Redis (`oauth_device:{flow_id}`) bound to the user and integration, and polls the token endpoint at the server's interval (`slow_down` honoured, early polls answered `pending` locally). |
| `client_certificate.parse_client_certificate` / `client_ssl_context(extra)` | Mutual TLS: validates a PEM certificate + matching key (+ passphrase) and builds the `ssl.SSLContext` transports present (cached per pair). The pair lives in the integration's encrypted `extra_config` (`client_certificate`, `client_private_key`, `client_private_key_password`). |

A provider helper that returns `(data, error)` or an error string - a GraphQL, tRPC or upload wrapper such as `github._common.gh_graphql`, `opencrq._common._trpc`, `opencti._common._graphql_upload` - words EVERY failure it writes itself with the `Error: ` prefix (`format_http_error` / `format_network_error` already do): a failure that does not read as one is stamped `is_error=False`, recorded as a success on the trace, missed by the error brake and, for a read tool, stored by the dedup cache, so a "retry shortly" retry is served the cached failure. Never widen `is_error_shaped_result` to catch a provider's own wording.

**All new providers should import and use these utilities instead of writing inline error handling.**

## Files (`file_delivery.py`)

Every tool that meets a file, a document, an attachment or media gives the agent four things at once, with no setting: the LINKS the source exposes (web / permalink and direct download URL, on listings, reads and downloads alike), a DOWNLOAD that stores the file as a file of the run (`persist_file_fn`, injected for the providers of `integration_tools._PERSIST_FILE_PROVIDERS` / `_PERSIST_FILE_CHANNEL_BOTS` - `tests/test_tool_result_files.py` fails when a provider reads the callback without being listed), the file on the tool RESULT (`ToolResult.files`: the model provider reads its text - `file_resolver.prepare_tool_result_attachments` extracts every non-image document, a PDF included, within the fallback cap - or sees its pixels within the vision budget), and a PIPE: every upload / attach / commit / import tool takes any `file_id` of the run. Build a download answer with `deliver_file(data=, filename=, content_type=, source=, persist_file_fn=, links=[("Web URL", ...), ("Download URL", ...)])` and resolve an upload's `file_id` with `read_pipe_file(file_context, file_id, max_bytes=, target=)`; never re-spell either. A download whose size nothing declared beforehand (an export, a signed link, a document endpoint, a meeting recording, an investigation package) goes through `fetch_file(client, method, url, provider=, action=, max_bytes=, **kwargs)`, which streams the answer and refuses it from its `Content-Length` or at the first chunk over the cap instead of holding it whole, reads an error answer up to 64 KB (on the wire and once decoded), closes every answer before it returns - it is the ONE download helper, never a second streaming loop in a provider - and follows a redirect itself: a hop that leaves the origin goes without the caller's headers (httpx only drops `Authorization`, never an API-key header), a hop that leaves HTTPS is refused, and a hop to any origin other than the one the download started on must pass the outbound URL policy (`validate_outbound_url_async`) so a signed link cannot bounce the platform to loopback, a private network or a metadata endpoint - the start origin itself is the caller's choice, which keeps a self-hosted instance on a private address working; never follow a download redirect with httpx's own `follow_redirects` while a credential other than `Authorization` rides on the request; name it with `content_disposition_filename()` (the `FetchedFile.filename` it returns) and type it with `file_content_type(declared, filename)`, which reads a `force-download` / `octet-stream` answer by the file's name. Its error is a `FetchError` (a `str`) that also carries `too_large` (with the declared `size`) or the refused `status`, for a tool that answers differently past the cap (a recording or a package keeps its link); on an `AutoRefreshClient` it streams through `AutoRefreshClient.stream()`, with the same single token refresh (a request not sent with the client's own token is never retried with it). A token-bearing download is sent only to the provider's own host (Slack `url_private_download`, WhatsApp media, ANY.RUN content), a signed URL is fetched without the token (Discord CDN, GitHub release assets, Notion / Drata / Figma exports, the Defender investigation package SAS link, Doppel screenshots, Google TI sample ZIPs; the Defender SAS link, like any URL an API answer hands over, is fetched through `social_media.fetch_public_media`, which holds every request, redirects included, to the outbound URL policy), and the channel-bot read / publish whitelists bound every file tool. The social post tools (LinkedIn, X, Facebook, Bluesky) share `providers/social_media.py`: `read_post_media` pipes the files of the run and checks each against the platform's DOCUMENTED type, size, pixel, frame, duration and count limits (`MediaLimits` / `MediaRule`, each rule citing its doc) before anything is uploaded, so a file the platform would refuse is refused naming the limit, and every raster image a post publishes carries `format_visual_summary()` on the result; `fetch_public_media` downloads a media link a platform served (signed CDN URL, public DID document or PDS) through `fetch_file`, without the account's token, HTTPS only and every request - redirects included - checked against the outbound URL policy first, up to `MAX_MEDIA_DOWNLOAD_BYTES`; every refusal keeps the link.

A file that can be live malware (a sample, a process or memory dump, a file dropped during a detonation, a file taken from an endpoint, a non-media file posted in an illicit community) goes through `deliver_live_artefact(data=, filename=, source=, persist_file_fn=, links=)` instead: it is stored only when it is a ZIP sealed with the vendors' `infected` password (`is_sealed_archive` - every entry encrypted and its password check read, the ZipCrypto header or the WinZip AES verifier, none of its content; the convention of ANY.RUN, CrowdStrike `password_protected=true`, Tanium evidence, Google TI `/intelligence/zip_files`), exactly as it came, and never carried on `ToolResult.files`, so the model never reads it (the platform reads a ZIP as no text and serves it as an attachment). Anything else, and any session without persistence, gets `live_artefact_links(filename=, source=, links=, reason=)` - the links and why it is not stored; a source known to serve such files unencrypted (Cortex XDR retrieved files) is linked without being fetched. The tool description says so.

What a source says about a file is third-party text: a document title, an attachment name, a SIEM lookup name, a provider's declared type, a `details` line (an alt text, a script preview) or a link. `deliver_file`, `deliver_live_artefact` and `live_artefact_links` print it only inside one `wrap_untrusted` block at the end of the answer (`untrusted_file_facts`: `Name:` and `Content type:` collapsed to one line each, then the details and the links). The answer's own lines come first and never quote it: the size, the source label, the `[[FILE:id]]` marker and the `file_id` line. The stored name, the `file_id`, the marker, the links and `ToolResult.files` are unchanged. A rule the platform itself gives about the file (1Password: share it only where its item may go) goes in `deliver_file(notes=)`, printed outside the block; a `details` line is read as data, so it never carries an instruction, and `notes` never carries a third party's text. A download answer built by hand (Drata, Notion, Google Drive, Microsoft, Teams bot) calls `untrusted_file_facts(source=, filename=, content_type=, details=, links=)` the same way. Never put a file name, a provider-given type, a detail line or a link in the open text of a download answer or of its error (an oversized file: `read_pipe_file` names it by its id, ThreatQ and Google TI put its name in the block). The same holds for an upload: the stored name of a file of the run is a third party's text too (a file downloaded from a provider, a name the user's client sent). An upload, attach, import or post tool names the file by its `file_id` in its answer, its own errors and the action label of its requests (`format_http_error` prints it), and ends its answer with `uploaded_file_answer(text, target=, filename=, content_type=, details=, links=)`: the stored name and what the target answered about the uploaded file (its name, title, type, a URL that carries the name) in one block. The name and the bytes sent to the target are unchanged. The hostile-name table is `tests.integration_file_fakes.HOSTILE_FILE_NAMES`; `fenced_and_open()` splits an answer into its fenced and open text and `assert_name_only_inside()` checks an upload answer, for a provider test.

## Stale references (`stale_references.py`)

A provider that can tell a resource is MISSING (a 404 on the resource's own path) and that the miss is SUSTAINED - the same resource, through the same integration, missing in separate runs - reports it with `report_stale_reference(provider=, provider_label=, integration_id=, resource_type=, resource_id=, failing_runs=, key=)`, and calls `confirm_reference_alive()` when the same resource answers later in the run. Never report a first-time miss: it can be the agent's own typo. Never report an id the run only READ off another resource (a relation target in a database the integration cannot see, a child block, a search hit): that is data, not the run's configuration - but when the run later ADDRESSES that id, report it, whatever the read left in a per-run cache. A type probe's miss (is this id a data source?) is not a missing resource either: withdraw once anything proves the id exists - it answered, a write naming it succeeded (a page created under that parent), or the API said it is another type. The assignment engine collects the reports around the agent loop, fails the run on them (`stale_integration_reference`, the summary kept) and pauses the assignment after `ASSIGNMENT_STALE_REFERENCE_PAUSE_AFTER` consecutive scheduled runs; outside a collecting run (chat) reporting is a no-op. Notion is the reference implementation (`providers/notion/_common.py`: the cross-run Redis counter, reported from `_bump_stale_ref` and from the pre-call suppression, `request(..., report_stale=False)` for the ids it only read, withdrawn by `note_resource_alive()` - the success self-heal, a 400 "is a page, not a database", a created or moved page's parent; the awaited bump is bounded by `_STALE_REF_BUMP_TIMEOUT_SECS` and runs outside the concurrency slot). Report only what the provider's own detector established, and keep the tool result the agent reads unchanged - the signal is for the run, not the prompt.
