# Frontend common pitfalls

Read before touching shared components, hooks, or the chat panel host (`components/chat-panel/`, `pages/chat-panel/`).

- NEVER use `useState` for data that comes from the API – use TanStack Query
- NEVER use inline styles – use Tailwind classes
- NEVER hardcode colors – use design-system tokens (e.g., `text-accent` not `text-[#00d4ff]`)
- NEVER use `white/N` or `black/N` alpha overlays for surfaces, hover or borders, and NEVER hardcode dark `hsl()`/hex backgrounds – use the elevation tokens (`bg-elevation-hover`, `border-elevation-subtle`, `layer-2 bg-elevation-default`). These break light mode; see Theming in `frontend-design-system.md`.
- NEVER reimplement a component the design system ships, and never approximate one with raw Tailwind. If it is missing, file it in `fds-migration/LIBRARY-FEEDBACK.md` and say so in review – a local fork is a coherence leak no gate can detect.
- NEVER edit the design system's tokens. `theme.css` is generated from Figma; a host-side override belongs in `index.css` (see the three product tokens in `frontend-design-system.md`).
- NEVER use native checkboxes – always use `Switch` toggle component
- ALWAYS give mutation feedback through `useToast()` (`success` / `error` / `info`)
- `yarn typecheck` is TypeScript 7, which has no JavaScript compiler API: a script that reads TS source parses it with `oxc-parser`. `yarn lint` is oxlint (`.oxlintrc.json`); `eslint-disable` comments still apply
- ALWAYS add every key you pass to `t_i18n("...")` to all four catalogs (`src/i18n/lang/{en,fr,es,ja}.json`: en = the id, real fr / es / ja translations, same placeholders, ja plurals `other` only). A missing key silently renders its English id to fr / es / ja users, so `yarn validate:i18n` (CI: Frontend > "i18n catalogs") scans the source and fails on it: every literal argument, and each literal branch of a `cond ? "A" : "B"` argument, is a key. Copy translated through a dynamic key (`t_i18n(LABELS[kind])`) lives in a module-scope literal table closed by `as const` and tagged `@i18n-keys` in its JSDoc, so the scan reads its values too (`scripts/lib/i18n-source-keys.mjs`); every value of such a table must be a string literal (a number, a `${}` template, an identifier or a spread in it fails the check); any other dynamic key is invisible to the gate
- NEVER pass `LABELS[value]` straight to `t_i18n` when `value` comes from the server: a key the table lacks is `undefined` at runtime whatever the type says. Read it through a lookup with a fallback (`findingKindLabel()` / `lockLabel()` returning `null`, or `LABELS[value] ?? value`), and keep the table equal to the backend's list with a test. `t_i18n` logs a missing id and renders nothing instead of throwing, but the label is still lost
- ALWAYS use `cn()` for conditional classes (never string concatenation)
- ALWAYS add types to `types/index.ts` when adding new API responses
- ALWAYS add hooks to the appropriate file under `hooks/api/` (e.g. `useAgentApi.ts`, `useAssignmentApi.ts`, etc.) – import directly from the domain module, no barrel re-exports
- ALWAYS use shared constants from `lib/constants.ts` (ICON_MAP, STATUS_CONFIG, TRIGGER_TYPES, TRIGGER_ICONS, TRIGGER_LABELS, CRON_PRESETS, describeCron, PROVIDER_DISPLAY_NAMES, INTEGRATION_PROVIDER_NAMES, TRANSPORT_DISPLAY_NAMES, INTEGRATION_STATUS, INTEGRATION_TYPE_LABELS, PROVIDER_LOGOS, inferMCPLogo, ssoProviderLabel, DEFAULT_AI_LABEL_PROMPT, DEFAULT_HITL_PROMPT, LANGFUSE_DEFAULT_HOST, BACKEND_FETCH_LIMIT, REFETCH_INTERVAL_SLOW, REFETCH_INTERVAL_STANDARD, REFETCH_INTERVAL_FAST, COPY_FEEDBACK_DELAY, CONTENT_PREVIEW_LIMIT, AUDIT_ACTION_ICONS, AUDIT_ACTION_COLORS, AUDIT_ENTITY_LABELS, ALL_CHANNEL_TYPES, EXTERNAL_CHANNEL_TYPES, CHANNEL_TYPE_LABELS, CHANNEL_ROUTING_ICON_KEY, CHANNEL_ICONS, TOOL_DISPLAY_NAMES, toolDisplayName, needsReauthorization, SpeechRecognitionAPI, COMMON_TIMEZONES, MEMORY_SOURCE_LABELS, MEMORY_TYPE_CONFIG, DELEGATION_TOOL_NAMES, GA_HANDOVER_TYPES, BUILTIN_TOOLS, KB_DOCUMENT_ERROR_LABELS)

## Dead code

`yarn knip` (part of `yarn check` and of the CI "Dead code (knip)" step) fails on an unused file, export, type or dependency, configured in `frontend/knip.jsonc`. Delete what it reports, or drop the `export` when the file still uses it. An export kept for a reader knip cannot follow - a backend test that needs the `export` of the TS source it parses - carries a `/** @public */` tag on its declaration; whole-file exceptions are listed in `knip.jsonc` with their reason. Type an import as `import type { X } from "@/types"`, never inline `import("@/types").X`: knip does not see the inline form.
