# When adding new features

The root `AGENTS.md` keeps one line per entry, because every agent session loads it; this file holds the full contract. Add detail here, never to `AGENTS.md`.

## When Adding New Features

1. Does it need a **new agent template**? → `POST /api/v1/agents/templates` or seed data
2. Does it need a **new integration**? → See `backend/app/integrations/AGENTS.md`
3. Does it need a **new LLM provider**? → See `backend/app/llm/AGENTS.md`
4. Follow existing patterns – read neighboring AGENTS.md files first
5. Does it need a **new model**? → Add import to `backend/app/models/__init__.py` (centralized registry), then run Alembic migration. If the entity is shareable (carries `is_company_managed` / `shared_group_ids`), give it the complete visibility column set and register it in the `CompanyManagedEntity` union — see rule 19; a partial set is a 500 for every non-admin user.
6. Add types to `frontend/src/types/index.ts`
7. Add hooks to the appropriate file under `frontend/src/hooks/api/` (e.g. `useAgentApi.ts`, `useAssignmentApi.ts`, etc.)
8. Register new routes in `backend/app/main.py`
9. Use shared constants from `@/lib/constants.ts` — never redefine icon maps, status configs, provider names, or integration types locally
10. Use `timeAgo()`, `formatShortDate()`, `formatTime()`, `formatShortDateTime()`, `stripMarkdown()`, and `toggleArrayItem()` from `@/lib/utils.ts` instead of defining local helpers or inlining date formatting
11. Use `RunCard` component for displaying assignment runs
12. Use `StatCard` component for stat/KPI cards on detail page overview tabs (never duplicate the Card + icon + label + value + subtitle pattern)
13. Use `PROVIDER_DISPLAY_NAMES` from constants for LLM provider names, `INTEGRATION_PROVIDER_NAMES` for integration providers, and `TRANSPORT_DISPLAY_NAMES` for MCP transport types (avoids CSS capitalize pitfalls like "github" → "Github", "sse" → "Sse")
14. Use `useEntityFilter()` for entity list page search + tag filtering (never duplicate the pattern)
15. Use `CompanyManagedBadge` for company-managed badges (never manually compose Building2 + Badge)
16. Use `SearchInput` for entity list page search fields (never duplicate the Search icon + Input pattern)
17. Use `EmptyState` for entity list page zero-state cards (never duplicate the dashed-card + icon + CTA pattern)
18. Detail page tab types must be named `Tab` (not `MCPTab`, `ToolTab`, etc.)

Pass `user_group_ids` from `get_user_group_ids()` for three-tier visibility. **A model queried through either helper MUST declare the full column set** — `is_company_managed`, `shared_group_ids`, `shared_group_permissions`, `shared_user_ids`, `shared_user_permissions`, `access_restricted` — **and be listed in the `CompanyManagedEntity` union in `helpers.py`**: the non-admin branch reads the per-user columns unconditionally, so a model missing them raises `AttributeError` at query-build time. **Exercise every such endpoint as a NON-ADMIN user** — `is_admin=True` short-circuits the predicate to `TRUE` before touching any column, so an admin-only test or manual check passes while every ordinary user gets a 500. That is not hypothetical: `flows`, `flow_event_types` and `nova_rules` were created with only the group columns, and `/flows` + `/chat` shipped to production 500ing for every non-admin caller while working for admins. `tests/test_visibility_helpers.py` now pins both halves over the whole union — a new shareable entity that skips either one fails there.

Use `canManageEntity()` from `lib/utils.ts` for every "may this user edit it" check (never inline the ternary pattern): it returns the server's tier-aware `can_manage` flag when the response carries it and otherwise opens edits to the owner and admins only (company-managed: admins), never to a grantee whose tier the payload does not state. Locks that are not about the user (built-in, system-managed KB, registration-only integration, a custom tool or KB installed by a skill package - `is_package_origin`, served by the API from the write guards' own predicate) are AND-ed on top by the page; `EntityConfigCard` then also gets the user's own right as `hasManageRights` (and `isBuiltin` / `isPackageOrigin`), so `configLockReason()` names the real reason instead of calling it a read-only share or telling an admin that only admins may edit. New consumer-specific fields belong in `extra_metadata`, not a new column.
82. Render every agent-generated deck through `components/presentation/PresentationDeck.tsx` and every human-readable string through the inline-markup tokenizer — a deck has NO HTML field, so no deck component may reach `dangerouslySetInnerHTML` (the Mermaid `Diagram.tsx` output is the one exception, pinned by `test_frontend_block_components_never_build_html_from_spec_text`), and never key the `Deck` on `revision` (that remounts the deck on every edit and resets the viewer to slide 1, breaking the required in-place update). New slide layouts need a Pydantic model in `presentation_spec.py`, a component in `layouts/index.tsx` AND an entry in `layout-options.ts`; adding one on a single side renders a blank slide or a picker that cannot offer it. Never bring a retired layout back as a model or a renderer: a stored v1 slide is upgraded by `presentation_legacy.py` on read (`SpecJSON`) and on write (`validate_spec`), and the tripwires in `tests/test_presentations.py` / `tests/test_presentation_spec_v2.py` fail the build on a second code path.
83. Use `api.postForm()` / `api.putForm()` from `lib/api.ts` for multipart uploads — never hand-roll a `fetch` with a `FormData` body (setting `Content-Type` yourself breaks the multipart boundary).
84. Author a `TemplateContainer` from an agent only through `build_template_authoring_tools()` (`app/services/builtin_tools/template_authoring.py`) — never re-spell the write validation in a new tool. A built-in container (`is_builtin_container()`) is duplicated, never edited: the startup seed full-syncs every field, so an edit is silently reverted by the next deploy. An agent never sets `is_company_managed` — publishing a template org-wide is a human action in the Templates UI, whatever the acting user's role.
85. Call `authorize_file_access()` (`app/services/file_access.py`) before letting any non-HTTP caller read or re-use a `FileAttachment` the caller named by id — a tool that trusts a bare file id can launder a file its user cannot download into an entity other people can read.
86. Render every agent-generated report through `components/report/ReportView.tsx` and sanitize every `rich_text` block with `sanitizeRichText()` — never pass block content to `dangerouslySetInnerHTML` directly. New report blocks need a Pydantic model in `report_spec.py` AND a `case` in `blocks.tsx`; adding one on a single side renders an invisible section (the tripwire is `test_frontend_renders_every_block_in_the_catalog`). A new `theme_config` key needs an entry in `REPORT_THEME_CONFIG_KEYS` **and** in `THEME_VARIABLES` in `ReportView.tsx` — a whitelisted key with no CSS variable is stored, served and silently ignored. Reports and decks share ONE definition of unsafe markup (`app/services/rich_text_guard.py`) and ONE channel-marker resolver (`_resolve_channel_artifact_markers` in `app/channels/base.py`): never fork either, a second copy falls behind and the scoping one is what keeps a marker from linking across conversations.
87. Build and parse a template package only through `app/services/template_package.py` — never re-spell the archive layout or its bounds in a route. Import goes through `validate_theme_config()` / `validate_layouts()` like any authored container, or import becomes the back door around them; it forces `is_company_managed=False` whatever the bundle claims; and it remaps asset ids into `layouts` / `extra_metadata`, since new rows mean new ids and a dangling reference renders as a missing image with no error anywhere. Parsing an uploaded archive is parsing hostile input: keep it bounded on entry count, uncompressed size and path shape (`_safe_asset_name`), and check every bound against bytes actually read, never against the archive's own declared sizes.

Use `formatDurationShort()` / `formatCountdown()` from `lib/utils.ts` for durations and countdowns (wait budgets in Settings, the chat wait countdown) — `formatDurationShort` mirrors the backend `format_wait_duration` so the same budget reads identically in the UI and in the tool result the agent sees; never inline `Math.floor(s / 60)` duration maths in page files.
89. Use `useResizableWidth()` from `hooks/useResizableWidth.ts` for any panel a user can widen by dragging its edge (the Presentation Studio rail and, with `edge: "start"`, the viewer's right-hand `PresentationSidePanel`, #3418) — bounds, pointer-capture drag, the WAI-ARIA window-splitter keyboard, double-click reset and the remembered width all live there; spread its `handleProps` on the divider, add the `aria-label`, and render the divider only when its `canResize` is true (never re-derive "is there room" from `min` / `max` in a component). Never hand-roll `pointermove` listeners on `window` for a resize edge, and never store a clamped width as the user's preference (the hook stores the preference and clamps it to the current viewport at render).
90. A chat transcript's scroll follow (the pin to the end, the scroll-to-bottom pill and its settle, #3483) is `@filigran/chatbot`'s — a host never scrolls the panel's transcript itself

Colour maths (`parse_hex_color()`, `delta_e()`, `format_hex()`) come from `app/core/color.py`; never re-spell them in a tool or a provider.
92. Read the scheme a SLIDE is drawn in through `resolveSlideScheme(presentation, slide)` (`components/presentation/theme.ts`) on the frontend and `resolved_slide_scheme(spec, slide)` (`presentation_spec.py`) on the backend — never off `spec.theme` alone: a slide may carry a theme of its own, and it always wins. A new slide host publishes `slideRootAttributes(resolution)` on its root and hands the resolution down through `SlideSchemeContext`; a component drawn inside a slide reads `--deck-*` tokens (inherited from the slide root), never the deck root's palette. A decorative layer under the content (a hero backdrop, a scrim) is an absolutely positioned descendant of the frame at a negative z-index — `.deck-slide` isolates for that — flagged `aria-hidden` and, when the PPTX must carry it as a picture, `data-export-backdrop`.
93. **Never hardcode a root-relative platform URL at a browser sink**: the platform may be served under a URL path prefix (`BASE_PATH`). In the frontend, an API request goes through `api.ts` (or `API_BASE` for a hand-rolled `fetch` / `WebSocket` / `EventSource`), a `window.location` / `window.open` / raw `<a href>` / `<img src>` takes its path through `withBasePath()` from `lib/base-path.ts`, a static asset held as data is prefixed where the string is defined (`providerLogoSrc()`, `PROVIDER_LOGOS`, `inferMCPLogo()` — never inline `` `/logos/${provider}.svg` `` at an `<img>`), a shareable link uses `absoluteUrl()`, and router navigation (`<Link to>`, `navigate()`) stays root-relative because `BrowserRouter` carries the prefix as `basename`. In the backend, a `RedirectResponse` or a URL written into HTML the browser resolves (`index.html` head links, the web manifest, the Scalar reference) goes through `with_base_path()` from `app/core/base_path.py`, and a middleware that keys on the request path reads `route_path(scope)`, never `scope["path"]`. A root-relative API path in an API payload (`download_url`, `platform_logo`, a `[[FILE:id]]` link) stays root-relative — the frontend prefixes it at the sink.
94. **A local path reaches the OS only through the Desktop shell's validated commands**: offer Open / Show in folder with `LocalPathActions` / `LocalPathLine` / `LocalPathInline` (`components/desktop/LocalPath.tsx`) — never `desktopInvoke("desktop_open_local_path")` from a component — gated on `canActOnLocalPath(runnerId)` so a card of ANOTHER machine only offers Copy, and never grant web content an `opener:` path permission (`open_path`, `reveal_item_in_dir`) or widen `OPENABLE_EXTENSIONS` (`apps/runner/src/local_paths.rs`) past passive content. A new `computer_use` capability reports its card through `RunnerActivity` in the tool funnel, never a second display channel.
95. A chat composer's attachments (tray, paste, drop zone, size check, the sent file's bubble) are `@filigran/chatbot`'s: a host passes its limits (`maxFileSize` = `MAX_CHAT_UPLOAD_SIZE_BYTES` in `XtmChatPanel`, `maxTotalSize` = `OFFICE_PANEL_MAX_UPLOAD_BYTES` in the Office add-in) and never builds a second tray, paste rule, drop zone or size check.
96. **A built-in suite is offered from ONE registry**: add its `BUILTIN_TOOLS` entry in `lib/constants.ts` (`agentOnly: true` when it acts as the agent - its traces, work queue, shared state - `gate` when a deployment switch hides it, a `tag` and its strings in en / fr / es / ja) and every picker - agent configuration, Settings > General Assistant, the profile override, the chat session picker - and the Tools pages offer it through `useBuiltinTools()`; never write a list of built-in ids or labels in a component. A suite whose deployment switch is off is never offered, but a screen editing a list that already carries one shows it so it can be removed, never added (the agent configuration through `listedInAgentConfig` / `toggledInAgentConfig`, #3857; Settings > General Assistant through its unoffered strip). A suite the General Assistant runs is also wired in `general_chat.py` and listed in `GENERAL_ASSISTANT_BUILTIN_TOOL_IDS`; an agent-only one is listed in `AGENT_KEYED_BUILTIN_TOOL_IDS` (`builtin_tools/filtering.py`), and a chat session - which REPLACES the agent's list - may only add one when the chatting user may configure the agent (`can_manage`, enforced in `agent_chat._bound_chat_session_builtin_tool_ids`; a flow's capability nodes extend the agent by design and pass `session_tools_from_flow=True`). The trace suites are the exception, decided on every turn by ONE rule, `agent_chat._turn_trace_tool_ids`: none in an A2A partner's task, and every one - carried by the agent itself, added by a session or a flow's Tool node, or implied by `agent_builder` - only for whoever may read the agent's chats (`builtin_tools.traces.may_read_agent_traces`, over `helpers.can_view_agent_chats`, the rule of the traces routes too); an assignment run checks the user it acts as, whoever triggered it included (`assignment_engine._add_run_trace_tools`); a flow save refuses a trace suite its writer adds on an agent they may not read (`flow_references.check_trace_tool_references`). The platform builder acts as `agent_chat._platform_builder_actor`: an external caller (an A2A partner's task, a channel sender with no account) gets its read half as an anonymous caller and no flow builder or evaluation tools. `tests/test_general_assistant_tools.py` pins all of it together and fails on a picker that carries a copy of the list.
97. **A page that loads something new says so in the Content-Security-Policy**: every HTML document carries the policy of `app/core/csp.py` (report-only by default, enforced on request), so a resource the policy does not allow is reported today and blocked on every deployment that enforces. A new server-rendered page registers what it needs beyond the SPA policy with `register_page_policy()` next to its template - extra sources, `script_hash_source()` of each inline script it writes, who may frame it - and binds its event handlers from its script (an inline `on*=` handler cannot be allowed by a hash); a new SPA feature that loads from another origin, frames a page, spawns a worker, or needs `eval` / WebAssembly extends `BASE_DIRECTIVES` in the same pull request, with its reason in a comment. Never allow scripts with `'unsafe-inline'`, never hash a response body, never add `X-Frame-Options`. `frontend/tests_e2e/csp-violations.spec.ts` fails on any violation of the key pages.
98. **A provider logo reads on both themes**: the files under `frontend/public/logos/` are drawn for the dark UI, and one rule at the end of `frontend/src/index.css` darkens, in light mode only, the ones drawn white or pale on a transparent background. It is keyed on the file, so it covers every `<img>` whatever handed it the path (`PROVIDER_LOGOS`, the backend catalog `logo`, a preset, a literal). A new logo like that adds its file to that list; never a per-call-site filter or `light:` class. `frontend/tests_e2e/provider-logo-themes.spec.ts` fails on an unlisted white mark and on a listed dark one.
99. **Fix the cause, generically** (#5303, invariant 18): before writing a fix, name the cause and the mechanism every agent, integration and language shares that removes it.
