| `SharedState`           | `shared_states`            | `shared_state.py`            | Generic cross-run shared state store: a `key -> value` record keyed by an exact `key` (unique per acting user), optional `workspace_id`. Lifecycle `status` `active` / `resolved` + `resolved_at`; the owning agent (`owner_agent_id`, defaulting to the creating agent) cleans up via `resolve_shared_state` / `delete_shared_state`, a retention sweep purges resolved entries and a derived `is_stale` flag surfaces neglected active ones. Size governance (#10789): `upsert_state` refuses a value over `shared_state_value_hard_limit_chars` (JSON characters, default 65,536, 0 disables) unless the write shrinks it, refuses a top-level list grown past `shared_state_list_max_items` (default 500, #11696), and answers `size_warning` over `shared_state_value_soft_limit_chars` (default 32,768); `serialize_state` carries `size_chars`, `largest_list` and `over_soft_limit` (`list_shared_state` tags `OVERSIZE`). An `archive_key` write (`archive=True`) stamps each item `_archived_at` and drops the archive's oldest items rather than pass the hard limit; the hourly sweep's `purge_archived_items` drops stamped items older than `shared_state_archive_retention_days` (default 14) from active entries, unstamped items never; an archive is capped at the list length too, and the tool refuses to archive an archive. Lifecycle (#11696): `is_lease` (an entry created by a take; resolved when its hold is released, by `upsert_state` or `release_ended_run_holds`), `value_updated_at` (moved only by a value change; staleness reads it, so notes never keep an entry fresh), `linked_work_item_id` (no key; `resolve_terminal_linked_states` resolves the entry once the item is done or cancelled), `expires_at` (`resolve_expired_states`), `terminal_condition` (text); the hourly `sweep_shared_state_lifecycle` runs both resolvers and `compact_oversize_states` (`compact_value`: oldest list items first, with a note). `held_by_run_id` (no key): the run holding the entry as a lease (`set_shared_state(hold="take")`); another run's take writes nothing while it lives and is answered as a `held` result (holder, the value's `pending_fix`), not a tool error, so no friction and no repeated-failure count; it takes the entry over once that run ended, and the scheduler tick's `release_ended_run_holds` clears the hold of a run that ended, each with a dated note. `retention` (JSONB, #11839): the list policy `{keep_last, max_chars, archive_key, lists, archive_when}` (`retention_shape`) applied by `upsert_state` on every value write (`roll_lists`, the rolled items appended to `archive_key` first). `archive_when` (#12035) is a terminal predicate in the `remove_json` match grammar: only matching items roll, oldest first, and `keep_last_json` on a governed list trims only them (`apply_list_ops(protect=...)`, `kept_open` in `list_changes`); open items kept past the cap are answered as `retention_held_open`, a roll without `archive_when` as `retention_rolled_by_age`; `serialize_state` carries `retention_usage` (size against `max_chars`, a warning at 80% of a cap). `max_item_chars` / `overflow_key` / `overflow_fields` / `item_key` (#12177): `spill_items` runs before the roll and moves the longest fields of an item over the cap (or the named fields of every item) to `overflow_key`, deep-merged under `{list: {item: {field: value}}}` and written before the source commits (`_write_overflow`), leaving an `overflow://` pointer; without `overflow_key` the write is refused. A spill by size never moves a number, a boolean, the identifying field, a `keep_fields` field, a field `archive_when` reads or a field shorter than its pointer, so `increment` and `where_json` keep working (#1760). `roll_open` (#1760, needs `archive_key`): once terminal items cannot bring a list under `keep_last` or the value under `max_chars`, the oldest open items roll into `archive_key` too, never dropped, and the "matches no item" warning is not raised. `keep_fields` (#754, needs `overflow_key` and `max_chars`): after the roll, `compact_open_items` moves the largest fields of the open items to `overflow_key` until the value fits `max_chars` (or the hard limit), never the identifying field, the named fields or the fields `archive_when` reads; the moved fields join `spilled`. An overflow key at the hard limit refuses the spill, which then rolls to its next part `BASE:part-2` (`overflow_part_key`, up to `OVERFLOW_RESOLVE_MAX_KEYS` parts) and `repoint_spilled` points this write's new pointers at that part before the source commits (`overflow_rolled_to`). #12320: `split_overflow_pointer` / `resolve_overflow_pointers` follow those pointers for `get_shared_state(resolve_overflow=true)` (each overflow key read once, at most `OVERFLOW_RESOLVE_MAX_KEYS`), and `apply_list_ops(fold=...)` (`fold_list_items`) merges object items sharing identity fields into the first (lists unioned, `sum` fields added, missing fields taken), `folded` in `list_changes`. A write answers `spilled` / `spilled_to`, `retention_unmatched` (`unmatched_archive_rule`: an `archive_when` matching no item while over `max_chars`) and `size_caps` (size against the soft and hard limits). |
