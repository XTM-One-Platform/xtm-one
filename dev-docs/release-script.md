# Release script

`scripts/release.sh` runs the full release flow: compute the next date-based
tag, create it, push it, and open a **draft** GitHub Release whose notes are
generated by an LLM from the commit history.

Tags follow `MAJOR.YYMMDD.SEQ` (see `release-management.md`).

## Prerequisites

- `git`
- `copilot` CLI (authenticated) — writes the release notes
- `gh` CLI (authenticated) — creates the draft release

## Common usage

```bash
scripts/release.sh                 # tag -> push -> draft release (default)
scripts/release.sh --dry-run       # preview version + plan + notes, change nothing
scripts/release.sh --notes-only    # only print generated notes
scripts/release.sh --no-release    # tag + push only
```

## Phase toggles

| Flag           | Effect                                     |
| -------------- | ------------------------------------------ |
| `--notes-only` | Only generate and print notes.             |
| `--dry-run`    | Compute version, print plan + notes only.  |
| `--no-tag`     | Use an existing tag (don't create one).    |
| `--no-push`    | Don't push the tag.                        |
| `--no-release` | Don't create/update the draft release.     |

## Options

| Flag            | Default          | Purpose                              |
| --------------- | ---------------- | ------------------------------------ |
| `--model NAME`  | Copilot default  | LLM model for note generation.       |
| `--major N`     | `1`              | Major version.                       |
| `--remote NAME` | `origin`         | Git remote.                          |
| `--ref REF`     | `HEAD`           | Commit/ref to tag.                   |
| `--tag TAG`     | —                | Operate on an existing tag (implies `--no-tag`). |

Re-draft notes for an existing tag:

```bash
scripts/release.sh --tag 1.260731.0 --no-push
```

The GitHub Release is always created as a **draft** — review and publish it
manually. Versioning logic lives in `scripts/create-release-tag.sh`; note
generation in `scripts/generate-release-notes.sh`.

## Notes on release-note generation

- The notes are authored by the local `copilot` CLI, so they are **not
  deterministic** — a `--dry-run` preview will read close to, but not byte-for-byte
  match, the notes an actual run publishes. Always review the published draft.
- Generation runs **locally**, not in CI. If `copilot` is missing or returns
  off-template output, the script prints a warning to stderr and falls back to a
  deterministic scaffold built straight from the commit history, so a release is
  always produced.
