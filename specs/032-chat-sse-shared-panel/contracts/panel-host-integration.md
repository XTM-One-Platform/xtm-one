# Contract: XTM One surfaces on `@filigran/chatbot`

How each surface maps onto the panel's props (FiligranHQ/filigran-ui#455, `packages/filigran-chatbot/src/types.ts`), and what the package adds for it. Where each piece of chat code lives, what XTM One keeps that the package also has and the contracts both repositories change together: `dev-docs/chat-panel.md`.

## Package gaps (FR-012, research R10)

All five ship in `@filigran/chatbot` 3.15.0 (FiligranHQ/filigran-ui#455); `frontend/package.json` and `apps/microsoft-office/package.json` pin 3.16.1 (T006), whose `theme` the web panel sets to the design system's tokens.

| Id | Gap | Package API | Needed by |
|---|---|---|---|
| G1 | Stylesheet isolated from the host: every utility scoped to `.filigran-chatbot`, theme variables on the panel root, no `:root` / `:host` rule (#3927, R9) | `postcss/isolate-from-host.js`, pinned by `postcss/stylesheet.test.js` | every surface |
| G2 | Inline layout without the conversation list, usable at rail and task-pane widths | `hideConversationList` | Studio rails, Office add-in, read-only view |
| G3 | Voice-call mode: listen → send → speak loop with barge-in and cancel, speaking only the final answer of the panel's own turn (or the turn a fold named) by the addressed agent; others shown by name, not spoken, "Did not answer" on `mention_failed` | `ChatPanelHandle.startVoiceCall()`, `voiceCallSupported()`; `ChatVoiceCall.tsx`, `useVoiceCall.ts`, `voiceCallController.ts`, `voiceTurn.ts` | voice-call overlay |
| G4 | A sent text distinct from the shown text | `onBeforeSend` returning `{ text, displayText }`; `handle.send(text, { displayText })` | Office add-in (document context) |
| G5 | The event stream closes once the page has been hidden for 60 s and reopens, resynced, when visible (research R8) | `useChat.ts` `EVENTS_HIDDEN_CLOSE_MS` | every surface on HTTP/1.1 |

## Shared host module

`frontend/src/components/chat-panel/XtmChatPanel.tsx` configures every web surface once (a surface inside a prefetched page loads it through `LazyXtmChatPanel.tsx`):

- `mode="inline"`, `backendType="rest"`, `apiBaseUrl = API_BASE` (`/api/v1`), `apiEndpoints = CHAT_PANEL_ENDPOINTS` (`endpoints.ts`): every `/web/chat/…` route of `contracts/web-chat-api.md` (`agents`, `messages`, `steer`, `approve`, `cancel`, `skipWait`, `pendingApprovals` and `events` = `/web/chat/conversations`, `sessions`, `history`, `messagesPage`, `clearAll`, `upload`, `prompts`, `suggestions`, `workspaces`, `conversationReferences`, `artifacts`), `download` = `/chat/files`, `tts` = `/chat/tts`; `quota: null` and `feedback` unset (the page's own `QuotaIndicator` and `MessageFeedbackButtons`). A route the panel has no default for must be named or the panel goes without it.
- `requestHeaders` from the session token (`useChatPanelHeaders`), `t` (`usePanelTranslate`) + `locale` (`panelLocale`) from the app's i18n, `accentColor` / `fontFamily` from the theme (`usePlatformLook`), `maxTotalSize` = `MAX_CHAT_UPLOAD_SIZE_BYTES`, `contextUsageEnabled` (the panel's own gauge).
- `markerRenderers` (`useMarkerRenderers`, `markers.tsx`): `FILE` (file chip with revisions), `PRESENTATION`, `REPORT`, `VIDEO`, `WORK_ITEM`, `INVESTIGATION`, each in `MarkerCardBoundary`, and `CHART` hiding the streamed marker; `codeBlockRenderers` = `CHART_CODE_BLOCK_RENDERERS` (a stored answer's chart fence drawn as `ChatChart`). `transformMessageText` (`messageTextForPage`, `message-text.ts`) resolves `[[SECRET_VARIABLE:…]]` and channel text, and shows an investigation's report as its block.
- `renderMessageExtras`: `MessageExtras` (a mentioned agent that did not answer, stored runner activity, expired approvals, unavailable integrations). `messageFooterActions`: `MessageFooterActions` (`MessageFeedbackButtons` with the feedback criteria, the trace for admins).
- `renderWaitingPanel`: the arcade `ChatWaitingGame`, its wait source `useArcadeWaitSignal(conversationId, working)`. `onSessionEnded` → `endSession()`. `onTaskComplete`: a toast, and the desktop window's attention when hidden. `onRelativeLinkClick`, `onDownloadError`.
- A surface passes `storedMessages` (its `useConversation` copy) and `working`. `useTurnFrames` (`pages/chat-panel/useTurnFrames.ts`) is its `onStreamEvent` + `onTurnRunningChange`: agentic charges, runner activity and approvals, what a pause waits on, query invalidation on `tool_done`, `presentation_saved` / `video_saved` (`handleToolProgress`, a studio's `onToolProgress`), the conversation refetched on a stored end, and `working`. `transcriptFooter()` (`transcript-footer.tsx`) and `useHostSender` (`host-send.ts`, a taken-over send keeps the composer's text until it lands) serve every surface.
