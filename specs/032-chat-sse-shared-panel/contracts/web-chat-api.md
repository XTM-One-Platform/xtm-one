# Contract: web chat API (`/api/v1/web/chat/*`)

The routes under `/api/v1/web` (`backend/app/api/v1/chat_web_stream.py`, research R3). The panel calls them with `apiBaseUrl = /api/v1` and endpoint paths starting `/web/chat/…` (`CHAT_PANEL_ENDPOINTS`, `frontend/src/components/chat-panel/endpoints.ts`), so the same base also reaches the existing `/api/v1/chat/tts` and `/api/v1/chat/files` routes; `backend/tests/test_chat_panel_contracts.py` checks every path the panel names against the served routes. These are also the public chat API scripts use (R13, `docs/docs/usage/chat-api.md`). Shapes follow the panel's README contract (FiligranHQ/filigran-ui#455, `packages/filigran-chatbot/README.md`, "API Contract" and "Turns that outlive their stream"); this file states only what XTM One adds or decides.

All routes: `Authorization: Bearer <access_token>`. The routes `chat_web_stream.py` defines take `web_chat_user` (`get_current_user`, then a session JWT only: 403 for an API key or a platform token); the reused handlers take `get_current_user` (R4). The routes that start or feed a turn (send, steer, approve, a new conversation from `POST /chat/sessions`, upload) also `require_chat_enabled` (`403 {detail, code:"chat_unavailable"}`, or `403 {detail:{code:"ai_disabled", message}}` with AI off); reads (a restore from `POST /chat/sessions` included), a session's own `PATCH` / `DELETE`, the events stream, pending approvals, Stop and Continue now stay open with AI off (specs/008-ai-disabled-mode). Conversations owned by the caller unless stated; a conversation shared with the caller restores and pages read-only (research R14). A route the panel calls with `X-Chat-Client-Id` records it as the request's `origin` (R6): at most 128 printable characters, any other value replaced by a random one for that request.

## Turn routes

| Method, path | Body | Answer | Notes |
|---|---|---|---|
| `POST /chat/messages` | `content`, `conversation_id`, `referenced_conversation_ids?`, `supports_tool_approval`, plus the host extras (below) (`WebChatSendRequest`) | `text/event-stream` (frames below) | Runs the turn, which outlives the stream (R1). Refusals before the turn → HTTP error with `detail` (R11). The turn treats its client as present while this stream is attached (`client_present`). Exempt from the admission limiter. |
| `POST /chat/messages/steer` | `conversation_id`, `content`, `steer_id?`, `file_ids?` (the panel sends them with `steerAttachments`) | `200 {status:"steered", steer_id, turn_id}`; `200 {status:"stored", steer_id, turn_id:null}` when the message stays in the thread with no turn known to have taken it, with `answered:false` when no turn took it for certain; `400` empty; `409` no turn running, including one that ended or stopped reading steering on the way (the message is withdrawn and the panel sends it as the next turn); `429` with `Retry-After`; `503` Redis down and the turn elsewhere, nothing stored | The message is stored first (`persist_web_steer`), then handed to the turn directly on its replica (`steer()`) or through the inbox (`fold_into_inflight_turn`); `user_message` is published once it stays. A steer the turn never read is answered by its exit follow-up pass (R5). |
| `POST /chat/messages/approve` | `conversation_id`, `decisions:[{tool_call_id, decision, rejection_reason?}]` | `200 {status:"accepted", decided}`; `400` no decision, or none naming a tool call; `404` another user's conversation; `409` nothing waiting (recorded); `422` a verdict other than `approve`, `approve_always`, `reject` | Pushed through Redis to the paused turn wherever it runs (`apply_approval_decisions`); the turn applies the decisions under the send's `impersonated_by`. |
| `POST /chat/messages/cancel` | `conversation_id`, `awaiting_send?` | `202 {status:"cancelled", turn: local\|remote\|none}`; `503` Redis down and the turn elsewhere | Direct on the turn's replica (`inject`), else `request_turn_cancel` plus `stop_conversation_work` (R5). With no turn and `awaiting_send`, the Stop is kept for the caller's send still on its way (`PENDING_CANCEL_TTL_SECONDS`); without it nothing is kept. The turn's streams end with `cancelled`. |
| `POST /chat/messages/skip-wait` | `conversation_id` | `202 {status:"wait_skipped", turn: local\|remote\|none}`; `503` as cancel | Direct on the turn's replica, else `chat:skip_wait:{id}` (R5). |
| `GET /chat/conversations/{id}/events?client_id=` | — | `text/event-stream` | `relay_turn_frames`, origin = `client_id` or `X-Chat-Client-Id` (R6). Owner only. Marks the client seen (`mark_client_seen`) on open and every `CLIENT_SEEN_REFRESH_SECONDS` (20 s); rechecks the session every 15 s; ends after `EVENTS_MAX_LIFETIME_SECONDS` (15 min) and the panel reopens it. Exempt from the admission limiter. |
| `GET /chat/conversations/{id}/pending-approvals` | — | `{conversation_id, proposals, turn: running\|idle}`; `404` another user's conversation; `503` when Redis cannot say | Recovery after a reload; marks the client seen. |

Host extras merged into the `POST /chat/messages` body (`getRequestExtras`, or a host send's `extras`), each a field the WebSocket send frame carried: `builtin_tool_ids`, `custom_tool_ids`, `integration_ids`, `mcp_server_ids`, `knowledge_base_ids`, `default_tool_ids`, `tool_selection_scope`, `scope_headers` (`useSessionTools().requestFields`), `file_ids`, `mode`, `source_pack_slugs`, `source_pack_options` (Deep Investigation), `studio_slide`, `studio_scene` (a studio rail's `sendContext`), `desktop_runner_id`, `mentioned_agent_ids`. Validation and meaning are unchanged.

## Stream frames

Every frame the WebSocket sent keeps its type and fields (FR-004; catalogue in `docs/docs/usage/chat-api.md` and `dev-docs/chat-turn-fanout.md`). The sample set is `frontend/src/pages/chat/stream-frames.contract.json`, checked against the backend's names and end rules by `backend/tests/test_chat_panel_contracts.py`. An `error` or `cancelled` marked `provisional: true` is provisional: the turn's final end follows, stored or, when the reply could not be stored, an `error` (`is_provisional_end`); any other end is final. Every frame but `user_message`, `conversation_title` and `session_expired` names its turn (`turn_id`), the send's `thinking` acknowledgement included (the transport names it once `turn_started` or `folded_into_active_turn` named the turn). Transport changes only:

| WebSocket | SSE |
|---|---|
| `pong`, client `ping` | `: keepalive` comment at most 15 s after the last write (R7) |
| close 4005 `session_expired:<reason>` | `{"type":"session_expired","reason":"lifetime"\|"idle"}`, then the stream ends; a later request answers `401 {"detail":{"code":"session_expired","reason","message"}}`; the panel calls `onSessionEnded` and the host signs out (`endSession`) |
| close 4001 / 4003 / 4004 at handshake | `401` / `403 {detail, code:"chat_unavailable"}` / `403 {detail, code:"terms_required"}` before the stream; `code` sits beside the same readable `detail` |
| close 1011 | `{"type":"error","content":…}`, then the stream ends |
| refusal `error` frames before the turn | HTTP error with `{"detail"}`: 400 empty or refused tool selection, 401 account, 404 unknown conversation, 409 channel hold, 422 pack options, 429 with `Retry-After` (R11) |
| `turn_started`, `folded_into_active_turn`, `steered`, `steer_error`, `wait_skipped` (socket-local) | `turn_started` / `folded_into_active_turn` on the message stream; steer and skip-wait answer their own POST |

A message stream folded into a running turn relays that turn's frames until its terminal (`done` without `intermediate`, `error` or `cancelled`), as the panel's README requires.
