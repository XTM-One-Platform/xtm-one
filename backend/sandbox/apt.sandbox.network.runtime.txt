# Keep this file's shared-library block (everything below down to proj-data)
# identical to apt.sandbox.extended.runtime.txt's contents — there's no build
# step that composes the two, so a change to the shared set (e.g. bumping
# libgdal36) must be hand-applied to both files.

# PLUS tshark/nmap: the ONE documented runtime-CLI exception in this feature
# (see spec.md Clarifications) — pyshark shells out to tshark, python-libnmap

# image may carry these two tools.
#

# dynamically links libkrb5.so.3/libgssapi_krb5.so.2 at import/use time
# (requests-kerberos header comment already lists libkrb5-dev as the
# build-time counterpart in apt.sandbox.extended.txt — this was the matching
# runtime half, missing until found by actually resolving the dependency
# chain with apt-cache against this Dockerfile's pinned base). apt pulls in
# libkrb5support0/libcom-err2/libk5crypto3/libkeyutils1 transitively.
